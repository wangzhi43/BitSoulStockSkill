# Token 配置

本 skill 需要有效的 `BITSOUL_TOKEN` 才能使用功能
token 可前往 <https://www.aicodingyard.com> 免费注册申请，并配置在外部运行环境中

## 必需的环境变量

* `BITSOUL_TOKEN`：用户令牌，用于远程服务器权限验证

## 可选的环境变量

* `BITSOUL_TOKEN_ENV_FILE`：指向包含 `BITSOUL_TOKEN` 的 env 文件


## 配置方式

1. **方式一：直接设置环境变量**
   ```bash
   export BITSOUL_TOKEN="你的令牌"
   ```

2. **方式二：使用 env 文件**
   ```bash
   export BITSOUL_TOKEN_ENV_FILE="/path/to/token.env"
   ```
   其中 `token.env` 文件内容格式为：
   ```
   BITSOUL_TOKEN=你的令牌
   ```
**注意**：如果同时设置了环境变量和 env 文件，环境变量优先。

## 运行时描述：
- 从环境变量读取 `BITSOUL_TOKEN`
- 只有在显式提供 `BITSOUL_TOKEN_ENV_FILE` 时，才会从文件中读取 `BITSOUL_TOKEN`
- 根据用户的自然语言，参考references/API_FOR_LLM.md 调用对应接口
- 对“分析 / 估值 / 基本面 / 趋势 / 风险”等请求自动切到综合分析, 需要moe因子计算，返回详细信息
- 对“交易观察 / 技术分析 / 均线 / 动量 / RSI / KDJ / 布林线 / MACD”等请求需要进行moe因子计算，同时需要调用calculate_metrics进行数据回测
- 返回结构化 JSON；查询场景优先给原始数据，分析场景给结论和支撑数据
- 任何返回的股票数据，都应包括个股的完整信息，不应遗漏任何字段

* **因子挖矿结束后**：在 `print(result['summary_text'])` 之后，用自然语言向用户逐一解释本次使用的每个因子是什么含义、在策略中起什么作用。解释来源是 `result['factor_descriptions']`，格式示例：`alpha022：高价量5日相关的5日变化 × 收盘波动率，用于衡量量价相关动量的衰减程度，在本次策略中作为选股因子使用。`
* **买卖建议**：用户询问某只股票"能不能买"、"该不该卖"、"现在适合持有吗"、"操作建议"、"投资建议"、"买卖信号"、"值得买吗"、"要不要买"等，且用户指定了具体股票时，请参考 `api.get_trade_signal(code)`

* **买卖信号输出格式**：调用 `get_trade_signal()` 后，按以下结构完整输出：

  2. **专家评分明细表**：列出 `result['experts']` 中所有专家（technical/alpha/fundamental/behavior），每个专家显示：评分、权重、有效指标数（valid_count/total_count）、note（若数据不足）
  3. **各专家关键细节**（从 details 中挑重要的展示，不需要逐项列举）：
     - `technical`：说明看多/看空/中性指标各多少个，点出最关键的 2~3 个指标信号
     - `behavior`：列出近5日涨跌幅、涨跌停次数等关键字段
     - `fundamental` / `alpha`：若有数据则简要说明核心结论
  4. **结论与建议**：引用 `reason` 字段，说明综合评分与阈值关系，给出操作建议

## A股回测合规性规则

以下规则是本 skill 回测系统的强制约束。任何调用本 skill 进行回测、模拟交易、因子挖矿的 AI 或外部程序，都必须严格遵守这些规则，否则回测结果无效。

### 1. 信号与成交时序

| 规则 | 说明 |
|------|------|
| 信号日 ≠ 成交日 | 选股信号必须使用**前一交易日**（T-1）的数据生成，不得使用当日（T）数据，否则构成未来函数 |
| 成交价 = 当日开盘价 | 所有买入和卖出均以交易日（T）的**开盘价**成交，不得使用收盘价、最高价、最低价或 VWAP |
| T+1 限制 | 当日买入的股票**当日不得卖出**。A股实行 T+1 交易制度，同一只股票的买入和卖出不能发生在同一个交易日 |

### 2. 交易数量约束

| 规则 | 说明 |
|------|------|
| 买入最小单位 | 买入数量必须为 **100 股（1手）的整数倍**，不足 100 股的零头必须向下取整丢弃 |
| 卖出不超过持仓 | 卖出股数不得超过当前实际持有股数，禁止空卖 |
| 资金充足性 | 买入时现金余额必须足够覆盖 `股价 × 股数 + 手续费`，禁止透支买入 |

### 3. 涨跌停与成交限制

| 规则 | 说明 |
|------|------|
| 一字涨停不可买入 | 当日开盘价、最高价、最低价、收盘价均等于涨停价时，视为一字涨停，**禁止买入** |
| 一字跌停不可卖出 | 当日开盘价、最高价、最低价、收盘价均等于跌停价时，视为一字跌停，**禁止卖出** |
| 无成交量不可交易 | 当日成交量为 0 或开盘价为空时，**禁止任何买卖操作**（视为停牌） |
| 涨跌幅按板块区分 | 主板（沪深）：±10%；创业板（300/301）：±20%；科创板（688/689）：±20%；北交所（.BJ）：±30%；ST/\*ST：±5% |
| 新股上市初期 | 注册制新股上市前 5 个交易日无涨跌幅限制，涨跌停拦截规则不适用 |

### 4. 交易费用模型

| 费用项 | 规则 |
|--------|------|
| 佣金 | 默认费率万三（0.03%），买卖双向收取 |
| 佣金最低限额 | 单笔佣金不足 **5 元**时，按 **5 元**收取 |
| 印花税 | 税率 0.05%，**仅卖出时收取**，买入不收 |
| 过户费 | 沪市收取（成交金额的十万分之一），深市不收 |

### 5. 持仓估值规则

| 规则 | 说明 |
|------|------|
| 估值价格 | 使用"当日及之前最近一条日线收盘价"进行持仓估值 |
| 停牌处理 | 停牌期间使用停牌前最后一个有效收盘价估值，**不得将持仓估值为 0** |
| 无交易日跳过 | 若当日全市场无任何股票数据（节假日），跳过该日，不进行交易和市值计算，避免虚假回撤 |

### 6. 复权处理

| 规则 | 说明 |
|------|------|
| 动量计算 | 近 N 日价格比较时必须叠加 `adj_factor` 复权因子，消除分红送股导致的价格突变 |
| 除权除息日 | 除权除息日 adj_factor 会突变，不得因此产生虚假的动量信号或止损触发 |

### 7. 数据质量校验

回测前和回测后应检查以下数据异常：

| 检查项 | 异常标准 |
|--------|----------|
| 单日价格跳变 | `|close/pre_close - 1| > 30%` 的样本需要标记排查 |
| 收盘价越界 | 收盘价超出理论涨跌停价范围（容差 0.2%）视为数据异常 |
| 开盘价越界 | 开盘价 > 涨停价 或 < 跌停价，视为数据异常 |
| 零量有价 | 成交量为 0 但有价格变动，视为数据填充错误 |

### 8. 审计检查清单

回测完成后，应通过 `audit_sim_runner.py` 执行以下合规性审计：

1. 买入股数是否为 100 股整数倍
2. 成交价是否等于当日开盘价
3. 是否误买入一字涨停 / 误卖出一字跌停
4. 数据库中是否存在 >30% 的单日价格跳变异常
5. 是否存在 T+1 违规（当日买入当日卖出）
6. 是否在停牌日（成交量为 0）产生了交易
7. ST/创业板/科创板/北交所涨跌幅阈值是否正确区分
8. 收盘价是否超出理论涨跌停价范围
9. 是否存在卖出股数超过持仓的空卖
10. 佣金是否满足最低 5 元限额
