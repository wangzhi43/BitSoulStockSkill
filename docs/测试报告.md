  - 买入股数未按 A 股 `100` 股整数倍约束

  - 首个交易日 `daily_return_pct` 计算错误，固定为 `0`

  - `stock_limit = 0`

  - `daily_bomb_list = 0`
- 这意味着当前版本只能基于日线和规则启发式处理一字板，尚不能精确覆盖“非一字涨停买不到 / 非一字跌停卖不掉 / 炸板 / 封板强弱 / 临停”等更细粒度可成交性。
- 继续排查后已确认：这三张表并不是导入失败，而是当前分发的 `data_1.0.bin` / `data_1.0 (7).bin` 源包本身未包含。
- 为了让回测器能够按标准表结构运行，已新增本地回填脚本，将现有日线推导为：
  - `stock_limit = 120660`
  - `daily_limit_list = 2040`
  - `daily_bomb_list = 1067`

## 4. 原始问题清单

### 已确认的明确问题

#### 问题 1：未来函数 / 穿越

- 原实现使用 `date` 当天数据评分，再直接用 `date` 当天 `close` 成交
- 这相当于“看到了当日收盘结果，再决定当天是否买卖”，不符合真实交易

#### 问题 2：成交价格口径不真实

- 原实现买卖都用当日 `close`
- 更合理的保守回测口径应为：
  - 前一交易日出信号
  - 当前交易日开盘成交

#### 问题 3：A 股买入手数错误

- 原实现股数直接 `int(预算 / price / 持仓数)`
- 可能出现买入 `1`、`37`、`289` 股之类记录，不符合 A 股普通股票买入规则

#### 问题 4：停牌 / 局部缺数估值不稳健

- 原实现估值直接查“当日行情”
- 若当天查不到，持仓价值不会用最近有效价兜底
- 这会在停牌、导入缺口、个股局部缺数时扭曲净值

#### 问题 5：首个交易日日收益率错误

- 原实现 `len(equity_curve) == 1` 时，用当天权益作为前一日权益
- 导致首个交易日 `daily_return_pct` 恒为 `0`
- 这与“从初始资金到首日收盘”的实际变化不一致

#### 问题 6：交易流水审计信息不足

- 原交易导出没有 `信号日期`
- 也没有明确 `成交价类型`
- 审计时无法直接判断是否遵守“前一日信号、当日开盘成交”

## 5. 已实施修复

### 修复 1：去除未来函数

- 改为：
  - `signal_date = 上一交易日`
  - 使用 `signal_date` 做选股与评分
  - 在 `date` 当天执行成交

### 修复 2：成交价改为开盘价

- 买入、卖出统一改为使用交易日 `open`
- 这样至少满足“先有信号，再在下一日可见价格成交”的基本客观性

### 修复 3：加入 A 股手数约束

- 新增 `normalize_buy_shares()`
- 买入股数强制向下取整到 `100` 股整数倍

### 修复 4：加入停牌 / 缺数估值兜底

- 新增 `load_latest_kline()`
- 估值时取“截至当天最近一条日线”的 `close`
- 避免持仓被错误估值为 `0`

### 修复 5：加入一字涨跌停成交拦截

- 新增：
  - `infer_limit_pct()`
  - `_price_limit()`
  - `_is_one_word_limit()`
  - `can_buy_on_row()`
  - `can_sell_on_row()`
- 当前规则：
  - 对日线可客观确认的一字涨停，禁止买入
  - 对日线可客观确认的一字跌停，禁止卖出
  - 且会优先读取 `stock_limit` 表中的正式涨跌停价，查不到时再回退到启发式推断

### 修复 6：评分对价格突变做复权修正

- `calculate_score()` 近 5 日动量比较时，叠加 `daily_basic.adj_factor`
- 尽量减少分红送股 / 除权除息导致的价格突变对评分的污染

### 修复 7：修正首个交易日日收益率

- 首日 `daily_return_pct = (首日总权益 - INITIAL_CASH) / INITIAL_CASH`
- 不再固定为 `0`

### 修复 8：增强交易流水可审计性

- 交易 CSV 新增字段：
  - `信号日期`
  - `成交价类型`

### 修复 9：补充涨跌停表本地回填脚本

- 新增 `claw_pool\backfill_limit_tables.py`
- 用现有 `daily_kline + stock_basic` 推导并回填：
  - `stock_limit`
  - `daily_limit_list`
  - `daily_bomb_list`
- 目的是让回测器与审计脚本都能按标准表结构读取涨跌停数据
- 这属于“本地推导版表”，能提升客观性，但不等同于官方逐笔或盘口级数据

## 7. 数据异常扫描

### 7.1 大幅价格跳变样本

数据库中扫描到若干 `abs(close / pre_close - 1) > 30%` 的样本，例如：

- `920078.BJ 2026-03-18 close=35.3 pre_close=6.98 pctChg=405.7307`
- `301696.SZ 2026-04-10 close=92.0 pre_close=24.68 pctChg=272.7715`
- `603459.SH 2026-04-08 close=57.7 pre_close=17.7 pctChg=225.9887`
- `300344.SZ 2026-03-31 close=0.5 pre_close=1.87 pctChg=-73.262`

### 7.2 对这些异常样本的判断

这些样本未必都是脏数据，可能来源于：

- 新股 / 次新股上市后价格机制变化
- 北交所标的高波动
- 除权除息或送转导致的口径变化
- 个别数据导入口径问题

### 7.3 本次处理策略

- 评分阶段已使用 `adj_factor` 尽量降低除权送股对动量判断的污染
- 但交易执行阶段仍使用原始市场价成交，这是对“真实可成交价格”的保守选择
- 若后续需要“收益分析”与“成交仿真”同时高精度，建议拆分：
  - 信号与收益评估用复权价
  - 交易执行与涨跌停约束用原始价

## 8. 仍然存在的风险与漏洞

### 风险 1：涨跌停表为空，当前只能启发式判断

- 该风险已由“完全为空”降级为“本地推导版，不是官方源数据”
- 虽然当前已能通过标准表结构提供涨跌停价和封板/炸板近似信息，但以下情况仍无法精确判断：
  - 非一字涨停但开盘后快速封板，实际可能买不到
  - 非一字跌停但开盘后快速封死，实际可能卖不掉
  - 炸板、回封、临停、盘口流动性不足

### 风险 2：没有滑点模型

- 当前成交按开盘价且仅收取固定手续费
- 未模拟：
  - 买卖价差
  - 成交冲击成本
  - 开盘价可成交量限制

### 风险 3：缺少正式成交量约束

- 目前只要求 `volume > 0`
- 但没有约束“下单量不能超过当日成交量某个比例”
- 对小盘股、北交所、冷门股，可能仍偏乐观

### 风险 4：收益统计仍以日线收盘估值

- 这是日频回测的常见做法，基本合理
- 但如果未来要做更真实的 T+1 / 分时成交 / 开盘换仓回测，仍建议引入更细粒度数据

## 9. 是否可以认定为“真实可用”

### 当前判断

可认定为：

- **明显比原实现客观得多**
- **已消除若干关键的伪收益来源**
- **可以作为日频策略迭代与参数筛选的基础版本**

不能完全认定为：

- **严格意义上的真实可成交回测系统**

### 原因

仍缺少以下关键数据或机制：

- 官方涨跌停价格表与官方封板/炸板榜单
- 盘口级炸板 / 封板 / 流动性数据
- 滑点模型
- 成交量容量约束
