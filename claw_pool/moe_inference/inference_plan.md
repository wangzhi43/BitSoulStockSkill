# 基于遗传算法的 MOE 权重逆向工程方案 (MOE Inference)

## 1. 目标
通过已知的目标账户历史交易记录（如 3月16日-3月30日 的买卖操作和每日持仓），利用遗传算法（Genetic Algorithm, GA）逆向推导出该账户所使用的 MOE 权重配置、买卖阈值、随机种子以及最大持仓数。最终利用拟合出的参数，在未来的时间段（如 3月31日之后）进行模拟，以尽可能逼近目标账户的真实交易行为。

## 2. 核心难点与解决思路
- **搜索空间巨大**：几十个因子权重、阈值、加上随机种子（$2^{32}$）和持仓数量。
  - **解决思路**：使用遗传算法进行全局启发式搜索。将权重、阈值、种子编码为“染色体”，通过适应度函数评估其优劣，经过选择、交叉、变异不断进化。
- **目标账户是否包含强随机性**：如果目标账户高度依赖每天变化的随机种子，完全复现极其困难。
  - **解决思路**：假设目标账户使用的是固定的 `seed`（目前模拟器中每个账户有一个固定的初始化 seed）。将 seed 也作为基因片段进行变异搜索。如果无法找到完全匹配的 seed，则退而求其次，拟合其“选股风格”（即使股票不完全一致，但选出的股票特征和收益率相似）。

## 3. 算法设计细节

### 3.1 基因编码 (Chromosome Encoding)
一个个体（染色体）代表一组完整的账户配置，包含：
1. **专家权重 (Expert Weights)**：`technical`, `alpha`, `fundamental`, `behavior` (需归一化)
2. **底层因子权重**：
   - 技术因子：`ma5`, `ma10`, `rsi` 等
   - Alpha因子：`momentum`, `reversal` 等
   - 基本面因子：`pe`, `pb` 等
   - 行为因子：`turnover`, `block` 等
3. **阈值 (Thresholds)**：`buy_threshold`, `sell_threshold`
4. **账户结构参数**：`seed` (0 到 $2^{32}-1$ 的整数), `max_holdings` (4 到 10 的整数)

### 3.2 适应度函数 (Fitness Function / 目标函数)
这是整个方案的**核心**。用来评估一组生成的权重跑出来的模拟交易结果，与目标账户真实交易记录的相似度。适应度越高（得分越高），说明拟合得越好。

**拟合度评分维度（满分 100 分）：**
1. **持仓重合度 (Position Overlap) - 权重 40%**：
   - 每天对比模拟账户和真实账户的持仓股票代码集合。
   - Jaccard 相似度：$|真实持仓 \cap 模拟持仓| / |真实持仓 \cup 模拟持仓|$。
2. **交易动作重合度 (Trade Action Overlap) - 权重 30%**：
   - 每天对比买入和卖出的动作是否一致（同日买入/卖出同一种股票）。
3. **仓位/金额相似度 (Capital Similarity) - 权重 15%**：
   - 对比模拟和真实账户每天的“总权益”和“持仓市值”的误差比例。
4. **持仓数量准确性 (Holdings Count Match) - 权重 15%**：
   - 比较每日持仓的数量是否一致，以推断 `max_holdings`。

### 3.3 进化机制 (Evolution Operations)
- **种群大小 (Population Size)**：例如每代 100-500 个个体。
- **选择 (Selection)**：采用锦标赛选择（Tournament Selection）或轮盘赌选择，保留适应度得分高的个体。
- **交叉 (Crossover)**：
   - 将两个优秀个体的因子权重进行混合（例如 A 提供技术因子权重，B 提供基本面因子权重，或者取两者权重的平均值）。
- **变异 (Mutation)**：
   - 以一定概率（如 10%）对某些权重加上随机扰动。
   - 以一定概率随机替换 `seed` 或 `max_holdings`。
- **精英保留 (Elitism)**：强制保留上一代得分最高的 Top 5% 个体直接进入下一代，防止负向进化。

## 4. 实施步骤

1. **数据准备阶段**：
   - 用户提供目标账户在指定日期范围内的**标准格式历史交易记录**和**每日持仓快照**。
   - 将这些数据解析为 Python 内部对象，供适应度函数快速比对。
2. **模拟器适配阶段**：
   - 改造当前的 `Account` 类，使其能够接受传入的基因（参数配置）并快速运行指定日期的模拟，**关闭不必要的文件 I/O 和日志打印**，以追求极致的运行速度。
3. **算法开发阶段**：
   - 编写遗传算法的框架（初始化种群、计算适应度、选择、交叉、变异）。
4. **运行与验证阶段**：
   - 运行算法迭代（例如 100 代）。
   - 输出得分最高的最优配置，将其保存为 `moe_weights.json`。
   - 使用该配置跑一次 3月31日 之后的模拟，观察是否符合预期。

## 5. 用户需求与系统设计确认 (已确认)

根据确认，系统将增加以下设计以满足具体需求：

### 5.1 数据输入模板 (已生成)
目标账户为**外部真实的实盘账户**。系统将通过读取两个 CSV 模板文件来获取真实数据，用于与模拟数据比对：
1. **`real_trades_template.csv`**：记录每日的买卖动作（日期、动作、股票代码、成交价、数量）。
2. **`real_daily_stats_template.csv`**：记录每日账户状态（日期、总权益、现金余额、持仓详情）。

### 5.2 适应度打分开关 (Fitness Switch)
由于目标是外部真实账户，完全精确复刻极其困难。算法默认**优先保证选的票一模一样**（即侧重持仓和交易动作的重合度）。
同时，提供一个参数开关（如 `--prioritize-equity`）：
- **默认模式（关）**：评分权重为：持仓重合度(50%) + 交易动作(30%) + 权益拟合度(20%)。
- **权益拟合模式（开）**：评分权重切换为：权益拟合度(60%) + 风格/持仓数量(30%) + 持仓重合度(10%)。此模式下，只要每天赚/亏的钱差不多（资金曲线拟合），即使买的不是同一只股票也会获得高分。

### 5.3 运行时间控制与断点续训 (Resumable & Time-boxed)
为了满足“单次拟合1小时内、支持多次续跑、支持随时中断”的需求：
1. **时间锁 (Time Box)**：算法每次启动会监听运行时间，当运行接近设定时间（如 3600 秒）时，会自动停止当前代数的计算，保存种群状态并退出。
2. **安全中断 (Graceful Exit)**：在运行过程中捕捉 `Ctrl+C` 信号。如果用户手动打断，系统不会直接崩溃，而是会把当前已完成的最佳结果和种群状态写入 `checkpoint.json`。
3. **断点续训 (Resume)**：脚本支持传入 `--resume checkpoint.json`。读取后，直接从上次结束的那一代继续往下进化，累加算力，从而得到更精确的结果。
